# Getting Started with JUI

JUI's canonical API is the Java-only `it.jui` API in `jui-core`.

## Requirements

- Java 25
- Maven 3.9+

## Build JUI locally

```bash
mvn -B -pl jui-core,jui-data -am install
```

For a standalone project, depend on the UI core:

```xml
<dependency>
    <groupId>com.jui</groupId>
    <artifactId>jui-core</artifactId>
    <version>0.0.1-SNAPSHOT</version>
</dependency>
```

Add `jui-data` only when CSV/JSON/JDBC DataFrame utilities are needed.

## Your first application

```java
import it.jui.Jui;
import it.jui.JuiApp;
import it.jui.UIContext;

public class HelloApp implements JuiApp {
    @Override
    public void run(UIContext ui) {
        ui.title("Hello JUI");
        ui.text("Everything in this application is described in Java.");
    }

    public static void main(String[] args) throws Exception {
        Jui.run(new HelloApp());
    }
}
```

By default JUI listens on `http://localhost:8080`. If the environment defines `PORT`, JUI uses it automatically.

## Interactive widgets

```java
String name = ui.textInput("Name", "Guest");
int age = ui.slider("Age", 0, 100, 25);
boolean active = ui.checkbox("Active", true);
String size = ui.radio("Size", List.of("S", "M", "L"), "M");
List<String> tags = ui.multiCheckbox("Tags", List.of("Java", "AI"), List.of("Java"));
String color = ui.colorPicker("Color", "#4f46e5");

if (ui.button("Save")) {
    ui.success("Saved " + name);
}
```

Interactive values survive rerenders through deterministic widget IDs. Buttons use one-shot events.

## Type-driven APIs

```java
record Customer(String name, String email, int age, boolean active) {}

ui.table("Customers", customers);
ui.metric("Customers", customers.size());
ui.form(Customer.class).ifPresent(customers::add);
ui.crud(Customer.class, customers);
```

Records keep declaration order. Bean-style POJO columns and forms are inferred from getter/setter conventions. Maps and scalar lists are also supported.

## Persistent CRUD

Implement `CrudRepository<T, ID>` when data is external or durable:

```java
public final class H2CustomerRepository
        implements CrudRepository<Customer, Long> {

    public List<Customer> findAll() { /* SELECT */ }
    public Long id(Customer value) { return value.id(); }
    public Customer create(Customer value) { /* INSERT */ }
    public Customer update(Long id, Customer value) { /* UPDATE */ }
    public void deleteById(Long id) { /* DELETE */ }
}
```

Then UI code remains storage-independent:

```java
ui.crud(Customer.class, repository);
```

## Layout

Nested UI is expressed with ordinary Java lambdas:

```java
ui.columns(
    () -> ui.metric("Customers", 42),
    () -> ui.metric("Revenue", 125000, "+12%")
);

ui.expander("Advanced", () -> ui.text("Options"));
ui.popover("Help", () -> ui.markdown("**Tip:** prefer records."));
ui.dialog("Details", () -> ui.table(customers));
```

For application navigation:

```java
ui.sidebar("App", List.of("Home", "Customers"), "Home", page -> {
    if (page.equals("Customers")) ui.crud(Customer.class, repository);
    else ui.header("Home");
});
```

## Text and media

```java
ui.markdown("# Report\n- item one\n- item two");
ui.code("record Customer(String name) {}", "java");
ui.caption("Generated by JUI");
ui.divider();
ui.bullets(List.of("one", "two"));

ui.image("/image.png", "Preview");
ui.audio("/sound.mp3");
ui.video("/movie.mp4");
```

Normal text is HTML-escaped. `ui.html(...)` is explicitly for trusted raw HTML.

## File upload

```java
ui.fileUploader("Document").ifPresent(file -> {
    byte[] bytes = file.bytes();
});
```

The default browser runtime limits inline uploads to 5 MB. Large files should use dedicated object storage/upload endpoints rather than JUI session state.

## Charts and interactive maps

```java
record Month(String name, int revenue, int cost) {}

ui.lineChart("Revenue", months, "name", "revenue", "cost");
ui.barChart("Revenue", months, "name", "revenue");

MapState state = ui.map("Naples", 40.8518, 14.2681, 12);
```

Charts use ApexCharts as a browser dependency. Maps use Leaflet; pan/zoom updates are returned as `MapState` through the normal rerun flow.

## jui-data

Add:

```xml
<dependency>
    <groupId>com.jui</groupId>
    <artifactId>jui-data</artifactId>
    <version>0.0.1-SNAPSHOT</version>
</dependency>
```

Then:

```java
DataFrame csv = DataFrames.readCsv("customers.csv");
DataFrame json = DataFrames.readJson(jsonString);
DataFrame sql = DataFrames.readSql(connection, "select * from customer");

ui.table(csv.select("name", "email").limit(100).toMaps());
```

## Google OAuth

Configure the server:

```java
JuiServer server = new JuiServer(new JuiProvider(new MyApp()))
        .googleOAuth(GoogleOAuthConfig.fromEnv());
server.start();
```

Set:

```text
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
GOOGLE_CALLBACK_URL
```

In the application:

```java
if (ui.authenticated()) {
    AuthUser user = ui.authUser().orElseThrow();
    ui.text("Hello " + user.name());
    ui.logoutButton("Logout");
} else {
    ui.googleLoginButton("Login with Google");
}
```

```bash
java -jar jui-core.jar init MyApp.java
java -jar jui-core.jar run MyApp.java
java -jar jui-core.jar watch MyApp.java
```

## Deployment

`JuiServer` reads `PORT`, so the same application can run locally or in a container. The repository's Vercel container runs `apps/jui-playground` in safe cloud demo mode. Dynamic compilation is disabled and the runtime image contains a JRE rather than a JDK.

Container instances should be considered stateless. Use an external database/service behind `CrudRepository` for durable business data.

The former `jui-core-old` module has been removed; all new code should use the canonical packages documented here.
